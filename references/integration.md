# 調整・デバッグ画面の組み込み

[Web見本](../assets/web/demo.html)はローカルのファイルとして開ける。「実行状態」の「ゲーム内時刻」と「更新回数」で、停止とコマ送りを確かめられる。重力と反発は実際のボールの動きに反映する。URLに `?debug=0` を付けると、作品だけの画面になる。

## Webで部品を使う

[debug-workbench.js](../assets/web/debug-workbench.js) と [debug-workbench.css](../assets/web/debug-workbench.css) を開発用の入口から読み込む。依存パッケージは不要。通常起動と同じファイルを使う場合は、既存の開発フラグを確認してから読み込む。フラグがなければローカルの開発版で `?debug=1` などを使う。

`mountWorkbench({ preview, clock, update, tuning, actions, readState })` に既存のプレビュー要素を渡す。プレビュー要素はラッパー内に移動するため、親要素を前提とするレイアウトでは開発用の差し込み先を用意する。

- `tuning` の各項目に `label`、`min`、`max`、`step`、`read()`、`write(value)` を渡す。`format(value)` で単位付きの表示にできる。
- `actions` に、作品固有の操作を試すための `{ label, run, enabled? }` を渡す。`enabled()` で端のレーンなどの条件を判定する。`actionsHint` には「押すと何が変わり、どこで確かめられるか」を短く書く。ボタンの上に表示される。`run()` が文字列を返すと、その結果がイベント履歴に残る。非同期の操作は `false` を返し、完了時に `record()` と `refresh()` を呼ぶ。
- 停止中に試す操作には `actionsWhilePaused: true` と `clock` を渡す。`clock.setPaused` があれば「手動操作」の中で「停止して試す」を押せる。すでに停止中ならそのまま操作を選べる。押した結果も同じカードに表示する。`clock.step` と `update` をつなぐと「1コマ進む」までその場で試せる。
- `readState()` は表示名と値の組を返す。扱う場面に応じて、現在の画面、進行段階、位置、速度、入力判定、シードなどを表示する。履歴への追加は `record(message)`、画面への反映は `refresh()`、取り外しは `destroy()` を使う。
- 静的モックでは `clock` と `update` を省き、画面・データ・表示の切り替えを実際のモックにつなぐ。

### 最小構成

```js
const panel = GameDebugWorkbench.mountWorkbench({
  preview: document.querySelector('.preview'),
  readState: () => ({ 画面: game.currentScreen }),
})
```

この構成ではプレビューと状態を表示できる。時間が進む作品では、下の「作品の時間を制御する」の例で既存の更新ループに時計をつなぐ。

| 使いたい機能 | 作品と共通部品の接続 |
| --- | --- |
| 作業環境の保存 | `workPresets: { storageKey }`。配置は `layout`、場面は `scenes`、調整値は `tuning`、表示サイズは `viewports` から取り込む。下記の復元に対応すれば進行中のコマも保存する |
| イベントで自動停止 | `events: [{ id, label }]` と同期的に停止できる時計。作品で表示や判定を確定した時に `panel.notifyEvent(id)` を呼ぶ |
| 再現情報を貼り付け | `reproduction: {}` と、作品ID・保存版・検証関数を持つ `sceneSaves`。時計がある場合は `clock.restoreState` も必要 |
| 同じ操作でA/B比較 | 上記の状態保存、`tuning`、`tuningPresets`、固定更新の前後を通知する時計、`replay: { deterministic: true, applyInput }`。[再生部品](../assets/web/workbench-replay.js)を取り付け前に読み込む |

## 作業名で確認環境を呼び出す

場面、調整値、表示サイズ、カード配置を整えて「作業環境」を開く。配置を使う盤では上部の同名ボタンから開ける。「作業名」に名前を入れてEnterを押すと、接続済みの項目がまとまって保存される。「保存した作業環境」から選ぶと、カードの開閉状態も戻る。例えば、吹き出し直前の場面を読み込み、スマホ幅を選び、セリフの表示時間を調整するカードを上段に移して保存する。

最後に保存または呼び出した作業は「更新・削除」から上書きできる。配置だけを保存するときは「配置を編集」から「配置を新規保存」を使う。「元の配置に戻す」は配置を切り替える前のカード位置・幅・高さを1回だけ復元する。作業の呼び出しで読み込んだゲームの場面や調整値はそのまま使える。

復元データを作れる場合は保存時点の作品状態と時計を戻す。場面の読み込みだけを提供する作品では、保存時に選んでいた場面の `load()` を使う。場面もない静的モックでは、接続済みの項目だけを戻す。配置、A/B、個別の場面、作業には別々の保存キーを使う。作業を呼び出しても個別の保存枠は使える。

時計をつないだ盤では、プレビュー上部でも停止・再開とコマ送りができる。停止中の「1コマ進む」と「1コマ戻る」は、短く押すと1コマ、長押しすると連続で動く。指やマウスを離すか、ボタンの外へずらすと止まる。キーボードではボタンにフォーカスしてSpaceかEnterを長押しする。戻れるのは履歴の先頭まで。ゲーム側で停止中の入力を受け付けない場合は、見本のようにプレビューの操作案内を切り替える。

## イベントが起きたコマで止める

```js
// パネルの設定例
events: [{ id: 'speech', label: '吹き出しが出る' }]

// 作品側。非表示から表示に変わった更新で一度だけ呼ぶ。
bubble.visible = true
panel.notifyEvent('speech')
```

「イベントで自動停止」で条件を選ぶと、プレイ中にその条件が成立したコマで止まる。すぐに確認するには「発生まで進む」を押す。共通時計は既存の描画ループで1回につき最大60コマ進める。選んだイベントの更新を終えたところで止まり、見つからなければゲーム内60秒で停止する。プレイヤー操作が必要なイベントは通常どおり入力する。記録と再生の間はイベントをログに残し、比較の終了コマまで進める。

独自時計で通常の自動停止を使うには、通知を受けた固定更新の直後から次の更新を抑止する。`iframe` 越しの非同期通知では親から停止を送り返す間に進むことがある。正確な停止が必要な作品ではゲームのループと同じ側にイベント判定と時計を置く。早送り探索を提供する時計は `seekEvent(onLimit)` で同じ更新を進め、上限に達したら停止して `onLimit()` を呼ぶ。

## 別の環境で再現する

```js
sceneSaves: {
  storageKey: 'my-game.debug.scenes.v1',
  gameId: 'my-game', stateVersion: 1,
  capture: () => game.saveSimulation(),
  validateState: state => game.isValidSimulation(state),
  restore: state => game.restoreSimulation(state),
},
reproduction: { read: () => ({ phase: game.phase }) },
```

作品IDは端末が変わっても同じ文字列を使う。`stateVersion` は1以上の整数とし、状態、調整項目、更新刻みの意味が変わったら上げる。`capture()` には乱数生成器の現在値、進行フラグ、保留中のゲーム内処理など、次のコマに影響する値を含める。`validateState(state)` は同期的に、作品を変更せず、型、範囲、項目間の整合性を検査し、有効なときだけ `true` を返す。`restore()` は受け取った状態を一括で反映する。

「再現情報をコピー」で取得したJSONを、別の環境の同じ作品で「JSONを貼り付けて復元」に貼る。共通部品が復元に使うのは `restorePoint` 内の作品状態、調整値、場面、時計。外側の状態表示、ログ、プレビュー幅は調査用。「診断情報だけをコピー」はログの共有に使う。作品ID、版、形式、値が合わなければ、時計を止めたり値を書き込んだりする前に理由が表示される。復元成功後は停止した状態で調査を続けられる。復元中に作品が失敗した場合は直前の状態へ戻し、戻せなかった場合はその旨を表示する。

## 同じ入力をA/Bで試す

1. パネルに `replay: { deterministic: true, applyInput }` を渡す。タップやキーは `panel.input({ type: 'jump' })` のようなJSONで渡す。ゲームの判定は `applyInput(input)` で同期的に行う。記録対象の入力を、元のイベントハンドラから二重に実行しない。
2. 調整値を変えて「Aに保存」「Bに保存」で2組を作り、開始場面を選ぶ。「記録を開始」を押してプレビューを操作し、「記録を終了」で止める。記録はこのページで保持し、次の記録開始時に入れ替える。
3. 「記録を再生」は記録時の値で再生する。「同じ操作でA/B比較」は同じ開始状態・乱数状態に2回戻り、各更新の前に同じ順番で入力する。同じ終了コマでの `readState()` の値を並べ、プレビューにはBの結果を表示する。

作品の判定には固定刻みと保存できる乱数生成器を使う。実時間、未記録の通信、`Math.random()` などに結果が依存する場合は、接続が整うまで `deterministic` を有効にしない。既存エンジンを使う場合は `clock.onTick(before, after)` が解除関数を返すようにする。各固定更新の直前に `before()` を呼び、falseなら進めない。成功時は作品を1回更新し、時計の更新回数を1増やしてから `after()` を呼ぶ。停止が入った描画フレームでは残った更新を打ち切る。コマ送りでも同じ経路を通す。

[ボールの接続例](../assets/web/demo.js)では跳ね上げ、[配達ゲームの接続例](../assets/web/lane-demo.js)ではレーン移動を入力として渡している。どちらも同じパネル、時計、配置、再生部品を読み込む。

## 共通パネルを追加する

- **場面**は `scenes: [{ id, label, load }]` を渡す。作品が起動時に設定した場面を `initialScene` で選択できる。切り替えとやり直しは同じ `load()` を呼ぶ。読み込み中は停止し、成功後は `clock.reset?.()` を呼んで停止を保つ。失敗時は選択と停止状態を元に戻す。非同期の `load()` が失敗しても、作品側で直前の場面を保てるようにする。
- **調整値**は `tuningPresets: {}` でA/Bの保存・適用・差分比較と既定値への復帰を追加する。保存する値には重複しない固定の `tuning[].id` を付ける。IDを省いた場合は表示名を使う。セッションをまたぐ場合は、作品ごとに異なる `storageKey` を指定する。保存形式や項目の意味を変えたらキーも変える。再読み込みで保存枠を読み出し、適用はボタンを押したときに行う。既定値にはパネル接続時の調整値を使う。
- **表示サイズ**は `viewports: [{ id, label, width, height }]` を渡すと、プレビューの上部に現れる。選んだ幅と高さをCSSピクセルでゲーム画面に適用し、「自動」で元の表示に戻す。プレビューを別の領域に移すと、この選択欄も一緒に移る。直接の子が `iframe` なら内部のビューポートも同じ寸法になる。通常のDOMはコンテナークエリや作品側のレスポンシブレイアウトで合わせる。通信を開始するiframeでは、マウント後に `src` を設定する。
- **再現情報**は `reproduction: { read: () => ({ /* 確認に必要な状態 */ }) }` を渡す。コピー内容は場面、表示サイズ、時刻・速度・更新回数、現在の調整値、`read()` の値、直近20件のイベント。コピーできない環境では選択済みのJSONを表示する。返り値の `getReproduction()` からも同じ内容を取得できる。共有する情報は調査に使う項目に絞り、個人情報や機密値を含めない。

## カードの色と配置

見出しには用途名が付き、左端の色で同じジャンルを追える。場面の切り替え・時間操作・手動操作・イベントで自動停止は緑の「操作」、パラメータと調整値の比較は黄の「調整」、プレビューは青の「表示」。実行状態とイベント履歴は紫の「状態・ログ」、作業環境・操作の記録・再現情報はピンクの「保存・再現」。カードを移動しても色と用途名は変わらない。

[workbench-board.js](../assets/web/workbench-board.js) と [workbench-board.css](../assets/web/workbench-board.css) を追加で読み込み、`mountWorkbench()` に `layout: { storageKey: '作品名.debug.layout.v1' }` を渡す。任意の `heading` に見出し要素を渡すと、配置メニューの横に表示する。見本を開いたら、そのままカードの移動とサイズ調整を試せる。

タイトルとゲームの切り替えを含む要素を `layout.header` に渡すと、配置・盤面幅・作業環境がタイトルと同じ行に並ぶ。入りきらない幅では「メニュー」から操作する。スマホではゲームの切り替えもここに入る。ナビゲーションの現在の作品に `aria-current="page"` を付けると、タイトル位置に作品名が残る。配置の編集中は「配置を保存…」と「編集を完了」がヘッダーに並ぶ。`destroy()` でヘッダーは元の位置に戻る。

ヘッダーの「表示するカード」で、この作品に接続したカードを選べる。隠してもゲームは動き、カードの位置や設定は残る。すべて隠したあとも同じメニューの「すべて表示」で戻せる。

標準配置で隠すカードは、例えば `layout: { storageKey: '作品名.debug.layout.v1', hiddenCards: ['actions', 'replay'] }` と指定する。表示設定のない旧データも作品の標準で開く。指定を省くと使えるカードがすべて表示される。保存済みの表示設定は作品の標準より優先する。

| 用途 | `hiddenCards` に指定できるID |
| --- | --- |
| 表示 | プレビュー `preview` |
| 操作 | 場面の切り替え `scenes`、時間操作 `time`、手動操作 `actions`、イベントで自動停止 `breakpoints` |
| 調整 | パラメータ `tuning`、調整値の保存・比較 `tuning-presets` |
| 状態・ログ | 実行状態 `state`、イベント `events` |
| 保存・再現 | 再現情報 `reproduction`、操作の記録・再生 `replay`、作業環境 `work-presets` |

上部の「盤面幅」はデバッグ盤全体に効く。「ウィンドウに合わせる」では親要素の利用可能な幅まで広がる。全幅で使うページでは、盤面を置く親要素の `max-width` を外しておく。「固定幅」は初回に現在の幅を取り込み、隣の数値欄で変更できる。Enterで確定する。画面より広い盤面は横にスクロールして使い、列数は盤面自体の幅で決まる。幅の設定は配置と作業の両方に保存される。以前の保存データは「ウィンドウに合わせる」で開く。

標準配置は、上段に場面と時間操作、左にプレビュー、中央に調整、右に状態やイベントを置く。よく使うカードに合わせて、組み込み側で標準配置を決める。カードには表示名から独立した固定のIDを付ける。追加したカードは標準の列に補い、削除したカードのIDは読み飛ばす。

カードの見出しをつかみ、置きたいカードの辺に線が出たら離す。左右に置くと同じ行に1列増え、上下に置くと新しい行ができる。例えば上段の「時間操作」の右に「パラメータ」を置くと3枚が横に並ぶ。その下に別の行を作るには、「実行状態」を「時間操作」の下辺に置く。空の下段にもドラッグ中は置き場所が現れる。折りたたみ式のカードは、見出しをクリックまたはタップすると開閉する。

タッチでは見出しの点々をつかんで移す。見出しの文字の上では縦にスクロールできる。キーボードではTabで見出しに移り、Alt＋Enterを押す。「移動先」でカードを選び、「置く位置」を指定して「ここに配置」で確定する。「下段の末尾」など領域を選ぶと、空の領域にも移動できる。

盤面幅が540px以下の標準配置ではプレビューが先頭に来る。カードを移動した配置や名前付きの配置では、保存した段と列の順序を使う。

通常表示のまま、各領域の左右の辺で幅を、下の辺で高さを調整できる。中央列の左端を左へ引くと左側に、右端を右へ引くと右側に広がる。反対の端はその位置に残る。領域内の空き幅を使い切ると、引いた側の隣の列が最小幅に達するまで広げられる。離した位置が幅の上限になる。

横に並んだカードは、間の縦線を引いて幅を分ける。標準配置の上段・下段では、その段の2列の配分が変わる。カードの左右の辺に別のカードを置いて作った行では、つかんだ境目の両側の2枚を調整できる。例えば3枚並んだ行で2枚目と3枚目の間を引くと、1枚目の幅は保たれる。

標準配置の上段・下段は、盤面幅が620px未満になると縦に並ぶ。自分で横に並べた行はスマホ幅でもその並びを保つ。収まらないカードは領域内で横にスクロールできる。

高さを抑えるには、領域の下端を上へ引く。例えば上段を180pxに縮めると、隠れた操作は上段の中をスクロールして使える。下に続きがある間は「↓ 下に続く」が出る。上限は80〜4000px。領域の辺をダブルクリックすると、幅や高さの上限を個別に解除できる。「配置を編集」では領域名の横の「戻す…」からも選べる。

キーボードでは、Tabで境界に移り、動かしたい方向の矢印キーを押す。外周は1pxずつ、Shiftと一緒に押すと10pxずつ動く。Homeはその辺の上限を解除する。カード間では左右キーで配分を微調整でき、Homeまたはダブルクリックで隣の2枚を均等に戻せる。ドラッグ途中の取り消しはEsc。

組み込み後は通常表示で、中央列の両端と横に並べたカードの境目を両方向に動かす。PC幅とスマホ幅で、見出しを押しただけでは配置が変わらないこと、プレビューやカード内のボタンを操作できることも確かめる。

カードの並び、幅と高さの上限、カード間の配分は、現在の配置、名前付きの配置、作業の保存に含まれる。「元の配置に戻す」で行の区切りも戻る。以前の保存データは、保存時の列幅と上下段の配分で開く。行の区切りを持たない配置は、上段・下段を2枚ずつ、ほかの領域を1枚ずつ並べる。

「戻す…」の「カード間の幅を標準に戻す」は、その領域の行ごとの配分を戻す。「列幅を標準に戻す」は上下段ならその段の共通配分、中央の列なら今の画面幅で横に並ぶ列の配分を戻す。ブラウザーに保存できない場合も、開いているページでは調整を続けられる。

読み込み済みの `iframe` は `Element.moveBefore()` で移動する。対応していないブラウザーではプレビューの位置を固定して、ほかのカードを動かせるようにする。プレビューを動かす前後でゲーム内時刻と再接続回数を比べる。

## 現在の場面を保存する

`sceneSaves: { storageKey, capture, restore }` を渡すと、場面パネルから名前を付けて保存できる。「場面を保存…」を押すと入力用の小窓が開く。保存後は同じ一覧から選択し、「読み込み直す」で保存地点に戻る。既存の `scenes` を省いて、保存機能だけを使うこともできる。

- `capture()` は同期的に、場面の復元に必要なデータをJSON化できる値で返す。複数の画面をまたぐモックやゲームでは、画面のID、進行、乱数なども含める。保存はその時点の状態を取り、再生・停止の状態を保つ。
- `restore(state)` で作品の状態を復元する。非同期の復元にも対応する。失敗した場合は変更を残さず例外を返すか、Promiseを拒否する。
- パネルの調整値も保存し、作品の復元処理の前に反映する。共通の時計では更新回数・速度を戻し、過去のコマ履歴を空にして停止する。外部の時計は `restoreState({ ticks, rate })` を提供すると同じように復元できる。時計を作品側で復元する場合は、読み込み成功後に共通パネルが呼ぶ `reset()` で復元値が消えないように接続する。
- `storageKey` を作品ごとに指定すると、同じブラウザーで開き直しても保存した場面を使える。キーを省いた場合やブラウザーに保存できない場合は、開いているページで保持する。状態の構造や意味を変えたらキーも変える。

## 作品の時間を制御する

独自のループでは `createPreviewClock()` を既存のループ内から使う。別の更新ループを作ると二重に進む。停止中も描画やパネル更新は続けられる。下の `deltaSeconds` は描画間の実時間を秒で渡す。

時間操作では見出しのそばに「停止中」「再生中」を表示する。停止とコマ送りはプレビューからも操作できる。長押しで同じ方向に何コマか動かすと、イベント履歴は連続した同じ操作を1件にまとめて回数を表示する。途中でゲームのイベントが起きると別の行になる。

標準の再生速度は0.25〜2倍で、スライダーと横の数値欄は0.01倍刻み。直接入力したらEnterで確定するか、別の操作に移る。Escで入力前の値に戻る。パラメータの数値欄も同じ操作で使え、各項目の `min`、`max`、`step` に従う。数値欄にはゲームに渡す値が入り、`format` はパーセントなどの表示に使う。

倍率を独自に設定するときは、例えば `createPreviewClock({ rates: [0.5, 1, 2, 3], rateRange: { min: 0.5, max: 3, step: 0.01 } })` と指定する。`rates` はショートカットの倍率で、1倍を含め、すべて範囲と刻みに合わせる。既存の `rates` だけの設定や外部時計は、登録した倍率を選ぶ方式を引き続き使う。外部時計で細かな調整を有効にするには、同じ `rateRange` を公開し、`setRate` と保存状態の復元でその刻みの倍率を受け付ける。

```js
const { createPreviewClock, mountWorkbench } = GameDebugWorkbench
const clock = createPreviewClock()
const tools = mountWorkbench({ preview, clock, update, readState })

// 既存の描画ループから呼ぶ。パネルは必要な頻度で更新する。
function frame(deltaSeconds) {
  clock.advance(deltaSeconds, update)
  render()
}
```

`advance()` は速度に応じて固定刻みの更新回数を変える。既に固定幅で更新している作品では、既存の時計を時間操作につなぐか、同じ刻みで時計を使う。タブを隠した時間を再開直後にまとめて進めないよう、描画時刻の基準を取り直す。

エンジンを使う場合は、既存のシーンや物理の停止・再開・時間倍率を使う。Webパネルに接続する場合の時計は `rates`、`state()`、`setPaused()`、`setRate()`、`step()` を接続する。対象を止めたまま安全に1更新できる入口がなければ、コマ送りを省いて、できる範囲の操作を表示する。アニメ、物理、ゲーム内タイマー、効果音は別々の時計を使う場合がある。停止と倍率の対象は作品ごとに決め、実際の場面で確認する。

プレイ入力は作品側で扱う。停止中にプレイ入力を止める場合は、押しっぱなしのキーやボタンも解除し、パネル自体は操作できるようにする。止めた時刻で試す入力は、必要な作品だけに専用ボタンとして用意する。

## 停止中に1コマ戻す

```js
const clock = createPreviewClock({
  history: {
    seconds: 5,
    capture: () => saveSimulationState(),
    restore: snapshot => restoreSimulationState(snapshot),
  },
})
```

各更新の直前に状態を保存する。`capture()` は位置・速度、進行フラグ、乱数の状態など、そのコマを再現するために必要な値の独立したコピーを返す。`restore()` はその値を同期的に復元する。戻った位置から進めると、現在の調整値と入力で次のコマを計算する。場面をやり直すと履歴が空になる。履歴は初期設定で約5秒、最大3,600コマ。記録するデータの量に合わせて保持時間を調整する。

公開済みの通信・保存・効果音など、作品の外に出た処理は復元の対象から外し、巻き戻しを使う開発環境では副作用を制御する。調整値とデバッグイベントは調整・調査のために残す。既存エンジンでは `canRewind()` と `rewind()` を時計側で提供し、時刻と状態を一緒に復元できる場面に限って表示する。
